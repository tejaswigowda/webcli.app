webCLI

Browser tools that take a URL and return an artifact. Every request is a GET, nothing you give them leaves your device, and there is no account. Pages that implement the agent surface below can be driven from a script.

Contract Tools Example Machines Privacy

The contract

URL in, artifact out. GET-only. Zero-egress. No account, no token, no upload. Same inputs give the same artifact: the output is a pure function of the input URLs and the parameters.

Zero-egress here means your input is never sent anywhere: no request carries a body, a cookie or a credential. A tool may still fetch static code, model weights or the input URLs you name, by GET. Where a tool does, its card says so.

The agent surface

A tool that implements it can be driven with no human in the loop:

  • run= in the URL query (or #fragment) starts the op as soon as the page loads.
  • window.__webcli_result holds the result: { ok, op, artifact, error, meta }.
  • [data-webcli-status] on <body> is the state: idle | running | done | error.
  • Stable data-testid hooks for the controls, listed on each tool's card.
// wait for the op to finish, then read the handle
await page.waitForSelector('body[data-webcli-status=done], body[data-webcli-status=error]');
const result = await page.evaluate(() => window.__webcli_result);

Not every tool has it yet. Each card says whether it does.

One worked example

For agents and scripts

The tool list on this page is rendered from one file. Fetch the same file directly:

curl -s https://webcli.app/tools.json
curl -s https://webcli.app/.well-known/webcli.json   # identical copy
curl -s https://webcli.app/tools.json | jq -r '.tools[] | select(.agent) | .origin'

The file carries "schema": 1. It is validated against schema/1.json; a breaking change bumps that number. Every entry in tools is live: origin resolves and source is a public repository, or null when it is not public yet. agent: true means the tool implements run= and the result handle; params and result describe them.

Privacy and licences

These tools process what you give them on your device. They do not upload it, do not need an account and do not set tracking identifiers. This page makes no request to any origin but its own, and a Content-Security-Policy enforces that; a CI test loads the page and fails on any other origin.

The worked example of the standard: the facebind privacy audit, a published check of one tool's zero-egress claim.

The one exception. The planned glb-fbx tool would have a cloud tier. That would be the family's only non-zero-egress path. If it ships, it is labelled as such on this page and on its card.
