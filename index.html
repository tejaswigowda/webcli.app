webCLI #

A family of browser tools that take a URL or a file and return an artifact, with your content processed on your device and no account; the paper explains the architecture. Loading code and models, and publishing to a repository, are the two declared exceptions below.

This index is itself built with blog-webCLI, from the webcli.app repository.

drop, chess and rtc share only-connect, which does not work across client-isolated networks; no TURN server is deployed.

The contract #

  • URL in, artifact out.
  • GET-only for loading. Input URLs, code and models are fetched with GET requests.
  • On-device processing. Your content stays on your device unless you explicitly publish it.
  • No account to process a file. Publishing tools require access to your repository.

Zero-egress is about your content, not about downloading the application. Each card declares what the tool fetches; hls and blog also publish to a repository when you ask them to.

The agent surface #

Implemented today by 3mf, look, portrait, rig (4 of 14 tools). The other tools do not have it yet.

  • run= in the URL starts the operation where supported.
  • window.__webcli_result holds the result: { ok, op, artifact, error, meta }.
  • [data-webcli-status] on the body reports idle, loading, running, done or error.
  • Stable test ids for each tool are listed on its card.
// wait for the operation to finish, then read the handle
await page.waitForSelector('body[data-webcli-status=done], body[data-webcli-status=error]');
const result = await page.evaluate(() => window.__webcli_result);

A worked example #

ImageMagick in a tab: sepia on a 480 by 320 PNG, nothing uploaded

14 requests during page load and the run: 9 to magick.webcli.app, 3 to cdnjs.cloudflare.com (icon font), 2 to cdn.jsdelivr.net (ImageMagick WebAssembly). All were GETs and none carried a body, so the image was in no request.

Historical measurement, verified 2026-10-20, Chromium, magick.webcli.app; not a new audit of the current application. Open DevTools, Network, then drop an image and press Process. magick has no run= surface yet, so this is the interactive path; the cards say which tools can be driven from a URL today.

Two exceptions, and they are part of the claim. Loading is egress: fetching the WebAssembly core and any model is a request, always a GET with no body, and each tool's fetches in tools.json names what it fetches. Measured on this page #

This page makes no request to any other host; CI loads it with a cold cache and fails on the first request that is not to its own origin, and the same check can be repeated in DevTools, Network, with Disable cache on.

Lab measurement of this page, median of 5: 0 JavaScript files, 3 requests, 148.7 KB transferred, first contentful paint 664 ms, largest contentful paint 664 ms, total blocking time 0 ms.

Method: blog-webCLI's cli/speed.mjs in headless Chrome: Slow 4G (1.6 Mbit/s down, 150 ms round trip), 4x CPU slowdown, a 390 px phone, a new browser profile for every run with the cache off, 5 runs, median reported; FCP and LCP from PerformanceObserver, total blocking time summed from long tasks after first paint; JavaScript counted from the network log. Lab data from one machine, served from 127.0.0.1, so the throttle supplies the latency but not DNS, TLS or distance; measured 2026-11-16.

For agents and scripts #

The tools are meant to be driven by a URL and to return an artifact; 4 of 14 (3mf, look, portrait, rig) have the run= surface today. tools.json is the machine-readable index of this page: for each tool its origin, what it fetches and, where it has one, that surface (parameters, window.__webcli_result, test ids). Nothing here needs an account; the two tools that publish are the exception stated above.

curl -s https://webcli.app/tools.json
curl -s https://webcli.app/tools.json | jq -r '.tools[] | select(.agent) | .origin'

The machine-readable index carries schema 4. A breaking change bumps that number; each entry declares its origin, state, inputs, outputs, egress, fetches and agent surface.

Privacy and licences #

Processing happens on your device. Loading can fetch code, models and input URLs; publishing is an explicit action that sends content to your repository. Each card names its boundary. This index itself makes no third-party requests and runs no JavaScript.

How the claim is checked:

  • portrait privacy audit (zero egress)
  • rig: how to verify zero egress, asserted by its test suite
